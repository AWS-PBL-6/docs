사고는 "순간", 대응은 불가능

고장력 계류삭이 파단되면 로프가 총알처럼 튕겨 나간다(스냅백). 사고 발생 후 대응은 불가능하며 사전 인지와 대피만이 유효한 대책.

국제 가이드라인도 인정한 한계

OCIMF MEG4는 스냅백 구역 고정 마킹을 권장하지 않기로 변경 — "전 범위의 정확한 계산이 불가능하고, 고정 마킹은 잘못된 안전감을 준다." 갑판 전체가 위험구역으로 남았다.

출처: 국내 통계 — 언론 보도(2022–2025 항만하역 재해 집계) · UK P&I Club 계류 사고 분석 · OCIMF Mooring Equipment Guidelines 4판

2 · 문제 정의

기존 솔루션은 비싸거나, 전조를 보지 못한다

자동 계류 시스템

Cavotec MoorMaster

진공 패드 자동계류. 실계약 기준 선석당 약 EUR 5M. 안벽 인프라 전면 교체가 전제 — 대형 터미널 전용.

하중 감시 계선훅

Trelleborg SmartHook 등

로드셀로 현재 장력만 측정. 파단 전조 신호(진동·음향 패턴)는 감지하지 못하고, QRH 훅 교체·개조 공사가 필요.

시장의 공백

재래 부두 · 중소 항만

AE 전용 계측 시스템도 채널당 약 550만 원 + 상시 계측 서버가 필요해, 볼라드식 재래 부두·중소 항만에는 상시 감시 수단이 사실상 없음.

그리고 규제는 강해지고 있다

  • 항만안전특별법 시행(2022) · 개정 공포(2026.3) — 항만재해 실태조사·통계 생산 의무화 방향
  • 중대재해처벌법 — 사업장 안전보건 관리체계·사고 원인 규명 데이터의 중요성 증가
  • 해양수산부, 스마트 항만안전플랫폼 부산항 시범 운영 후 전국 확산 추진 중

3 · 서비스 소개

센서 하나에서 대피 문자까지, 전 과정 자동

기존 볼라드·계류삭에 저비용 센서 노드를 부착하면, 측정 → AI 판정 → 관제 → 경보 전파가 사람 개입 없이 이어진다.

3단계 위험 판정

진동 이벤트 흐름을 AI가 정상 · 주의 · 위험으로 실시간 분류. 순간 노이즈는 3중 정책으로 걸러 오경보를 억제.

스냅백 위험반경

위험 확정 시 선박–홋줄–볼라드 기하와 장력 추정으로 파단 시 도달 구역을 동적 계산 — 고정 마킹의 한계를 넘는 접근.

부산항 3D 디지털 트윈

선박 접안 · 계류삭 색상(녹/황/적) · 볼라드 매핑 · 위험반경을 한 화면에서. 낮/밤 자동 전환 관제 뷰.

이메일 · SMS 즉시 전파

주의/위험 발생 즉시 등록 수신자에게 발송. 수신자·동의 관리 화면 내장, 발송 이력은 감사 가능하게 보존.

근거 있는 대응 지침

생성형 AI(RAG)가 승인된 공식 안전문서 7건에서 검색한 근거를 인용해 즉시 조치·후속 조치를 안내. 근거 없으면 답하지 않음.

감사 추적

센서 이벤트→판정→경보가 traceId 하나로 연결되어 저장 — 중대재해처벌법 대응·원인 규명의 데이터 근거.

4 · 구현 내역 및 AWS 아키텍처

기술 스택

Edge · IoT

수집

피에조 압전센서 · Arduino · HC-06 블루투스 · 노트북 게이트웨이(Python) · MQTT · AWS IoT Core / IoT Rule

Backend

처리·경보

AWS Lambda · API Gateway (REST + WebSocket) · DynamoDB · Amazon SNS (이메일·SMS) · CloudFormation(SAM)

ML · AI

분석

SageMaker (Processing · Training · Registry · Serverless Endpoint) · XGBoost 3-class · Amazon Bedrock Knowledge Base (RAG)

Frontend

관제

React 18 + TypeScript · three.js / React Three Fiber (3D 트윈) · Amplify Hosting · Cognito (Google 로그인)

데이터 — 근거 있는 합성

계류삭 AE 파단 실측 논문(Bashir et al. 2017, Applied Acoustics)의 통계 특성을 기반으로 합성한 뒤, 단위 변환·거리 감쇠·항만 소음(크레인·강우·바람)을 주입해 항만 도메인으로 변환. 라벨 누수 요소(Truth_*)는 학습에서 제외.

모델 — 윈도 판정

단일 측정값이 아닌 최근 12개 이벤트의 시계열 윈도에서 17개 특징(진폭·SNR·히트·신호군 조성·발생률·환경)을 집계해 판정. 학습·서빙이 동일 코드 계약을 공유해 불일치를 차단.

4 · 구현 내역 및 AWS 아키텍처

3-계층 서버리스 아키텍처

수집 · 분석 · 전파를 표준 이벤트 계약(JSON Schema)으로 연결 — 계층별 독립 개발·교체 가능

수집
피에조 → Arduino → BT 게이트웨이→ MQTT publish→ IoT Core + IoT Rule
분석
Lambda 검증·윈도 17특징→ SageMaker Serverless XGBoost→ 시간적 정책 + 주파수 대역 정책→ 스냅백 물리엔진 결정론적 반경 계산
전파
DynamoDB 저장→ WebSocket → 3D 트윈· SNS 이메일·SMS· Bedrock KB 검색 → 경보 리포트 생성
  • 스냅백 물리 계산은 Lambda의 결정론적 모듈이 수행 — 생성형 AI(Bedrock)는 계산 결과의 서술·리포트만 담당(환각 통제)
  • 전 리소스 IaC 배포 — CloudFormation 스택 하나(ae-sentinel-app), 재현 가능한 인프라
  • SageMaker 미연결·실센서 부재 환경에서도 내장 대체 분류기·가상 센서 모드로 팀 간 개발 비차단
  • 콜드스타트(~24초) 대비 — 원시 측정값을 추론 완료 전에 먼저 WebSocket으로 선반영

6 · 기대 효과 및 향후 계획

기대 효과

인명 안전

사고 후 대응 → 사고 전 대피

파단 전 단계 조기 경보(재현율 0.97)와 동적 위험반경, 자동 문자 전파로 대피·작업중지 판단 시간을 확보 — 스냅백 중대재해의 실질적 예방 수단.

경제성

82억 원 vs 1,220만 원

실 AE 계측 사양 기준 초기 224만 원, 5년 TCO 약 1,220만 원/선석 — 진공 자동계류(선석당 약 82억 원) 대비 약 1/670, 동일 기능 AE 전용 계측(채널당 550만 원 + 상시 서버) 대비 측점당 약 1/20. 안벽 공사 없이 기존 볼라드에 부착만.

규제 대응

중대재해처벌법 데이터 근거

이벤트→판정→경보의 전 과정이 traceId로 연결·보존되어 안전보건 관리체계 고도화와 사고 원인 규명의 감사 데이터로 활용 가능.

운영 효율

판단 부담을 낮추는 관제

3D 트윈의 공간적 직관 + 공식 문서 인용 대응 지침으로 관제 인력의 인지·판단 부담을 낮추고 대응 일관성을 확보. 상태 기반 로프 교체는 덤.
