# 센서 부착 위치 결정 — 안벽(지면) 볼라드 고정형

> 결정일: 2026-07-08 · 상태: 채택
> 관련: [시스템 인터페이스 계약](aws-system-repository-and-interface-contract.md), [권장 아키텍처](ae_sentinel_recommended_architecture.md)

## 결정

AE 센서는 **선박이 아닌 안벽(지면) 볼라드에 고정 설치**한다. 선박은 접안 세션 동안만
홋줄(계류삭)에 시간제로 매핑된다.

## 배경

기존 모델은 센서가 선박 측 볼라드에 부착되는 것을 전제했다
(`LineStatus.vesselId` — "ship whose bollard carries this line's sensor").
사업화 관점에서 검토한 결과, 입항하는 모든 선박에 센서 설치를 요구해야 하는
구조적 단점이 확인되어 안벽 고정형으로 전환한다.

## 비교

| | 선박 부착형 (기존 모델) | 안벽 볼라드 고정형 (채택) |
|---|---|---|
| **설치 대상** | 입항하는 불특정 다수 선박 — 국제 선박에 장비 탑재를 강제할 방법이 없음 | 선석당 볼라드 수십 개, 1회 설치 |
| **구매 결정자** | 선사를 일일이 설득해야 함 (항만 운영사와 계약해도 무용지물) | 고객 = 항만공사/터미널 운영사, 자산도 운영사 소유 |
| **전원·통신·유지보수** | 배터리, 무선, 선박별 교정·회수 물류 | 유선 전원/게이트웨이, 정기 점검으로 일원화 |
| **업계 선례** | 없음 | 하중 감시형 계선훅(QRH) 모니터링이 이미 안벽 쪽 방식 (Trelleborg, Mampaey 등) |

## 운영 흐름 (관리자 관점)

1. 센서는 볼라드에 상시 부착 — 평시에는 "미계선" 상태로 대기
2. 선박 접안으로 홋줄이 걸리면 AE/장력 신호로 **계선 자동 감지** → 해당 볼라드의
   라인 레코드 자동 활성화
3. 선박↔홋줄 매핑은 **접안 세션으로 자동 귀속**: 입항 등록(또는 AIS/Port-MIS 연동)으로
   "이 시간대, 이 선석 구간 = 이 선박"이 정해지면 그 구간 볼라드의 활성 홋줄이 전부
   해당 선박에 귀속. 관리자는 확인 1클릭(AIS 연동 시 완전 자동 가능)
4. 출항 시 장력 소실로 세션 종료, 볼라드는 다시 대기 상태

→ **선박당 하드웨어 소요 0, 라인별 수동 매핑 0.**

## 데이터 모델 영향

- `Bollard` 엔티티 신설: 안벽 고정 자산 (bollardId, siteId, berthId, 안벽 기준 위치)
- `LineStatus.bollardId`: 센서의 **영구 귀속처** (불변)
- `LineStatus.vesselId`: 접안 세션 동안만 붙는 **시간제 연결** (접안 시 부여, 출항 시 해제)
- 프론트 디지털 트윈(`frontend/src/twin/`)은 이미 지면 볼라드 기준으로 렌더링하므로
  화면 변경은 최소 — 배정 로직만 실데이터로 교체
