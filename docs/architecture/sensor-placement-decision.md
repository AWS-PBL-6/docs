# 센서 부착 위치 결정 — 계류삭 연결 고리 개별 부착형

## 결정

피에조 압전센서는 볼라드가 아니라 **각 계류삭의 선박 측 연결 고리(아이·스플라이스
인근)에 개별 부착**한다. 센서 한 대는 계류삭 한 가닥만 측정한다.

볼라드는 센서 자산이 아니라 계류삭이 연결되는 안벽 위치와 스냅백 기하를 나타내는
별도 엔티티로 유지한다.

## 변경 이유

볼라드 하나에는 계류삭이 최대 두 가닥까지 연결될 수 있다. 볼라드에 센서 한 대만 두면
어느 계류삭에서 발생한 진동인지 분리하기 어렵고, 각 계류삭의 장력·파손 징후를 독립적으로
관제할 수 없다. 반면 연결 고리/아이·스플라이스 인근에 부착하면 측정 신호와 `lineId`의
대응이 명확해진다.

## 비교

| 항목 | 볼라드 센서 1대 | 계류삭별 센서(채택) |
|---|---|---|
| 신호 귀속 | 볼라드에 여러 계류삭 연결 시 모호 | `sensorId ↔ lineId` 1:1 |
| 계류삭별 위험도 | 신호 분리/추정 필요 | 직접 분리 가능 |
| 설치 수량 | 볼라드 수 기준 | 동시에 관제할 계류삭 수 기준 |
| 현장 위치 | 안벽 고정 | 선박 측 연결 고리·아이·스플라이스 인근 |
| 운영 데이터 | 볼라드가 센서 소유 | 계류삭이 센서 소유, 볼라드는 위치만 제공 |

## 운영 흐름

1. AWS IoT Core에 피에조 센서 Thing을 등록한다.
2. 관리자가 선박과 계류삭을 등록한다.
3. 현장 작업자가 센서를 해당 계류삭 연결 고리에 부착한다.
4. 관리 화면에서 계류삭을 열고 AWS IoT 센서 목록에서 장비를 클릭 적용한다.
5. 센서는 `aesentinel/{sensorId}/piezo`로 `deviceId`, `lineId`, `freqHz`를 발행한다.
6. Backend는 등록된 `sensorId ↔ lineId`가 일치할 때만 추론을 수행한다.
7. 출항해도 센서 소유 관계는 계류삭에 남고, `vesselId`와 `bollardId` 운영 매핑만 변경한다.

## 데이터 모델 영향

- `LineStatus.sensorMode`: `PENDING | DEVICE | VIRTUAL`
- `LineStatus.sensorId`: AWS IoT Thing ID
- `LineStatus.sensorBoundAt`: 배정 시각
- `LineStatus.bollardId`: 안벽 연결 지점
- `LineStatus.vesselId`: 접안 세션 선박
- `Bollard`: 센서 필드 제거, 위치/선석/디지털 트윈 기하만 유지

## 마이그레이션 원칙

기존 `Bollard.sensorId`는 자동 이관하지 않는다. 한 볼라드에 복수 계류삭이 있을 수 있어
올바른 대상 라인을 기계적으로 결정할 수 없기 때문이다. 물리 센서를 실제 계류삭으로 옮긴
후 관리자가 해당 `lineId`에 다시 배정한다.
