# ML 데이터 출처 · 수집 · 작성 근거

> 기준일: 2026-07-14 · 결론부터 읽는 데이터 계보 문서

## 먼저 바로잡을 점

**현재 모델은 실제 부산항 계류삭 파단 데이터를 학습하지 않았다.**

- 실제 측정 근거: 영국 Exeter DMaC 설비의 폴리에스터 계류삭 파단 실험 논문
- 모델 학습 데이터: 논문 수치를 바탕으로 프로젝트가 만든 합성 데이터
- 항만 환경값: 비·바람·크레인·소음의 분포를 코드로 생성한 시나리오 값
- 실제 장치값: 운영 피에조 센서의 `freqHz`는 E2E 검증에는 썼지만 학습에는 쓰지 않았다.

따라서 “실환경 기반”은 **실험실 실측 물리 근거를 반영했다**는 뜻이지,
**우리 항만에서 직접 수집한 학습 데이터**라는 뜻이 아니다.

## 데이터 계보

| 단계 | 데이터 | 실측/합성 | 현재 용도 |
|---|---|---|---|
| 1 | Bashir et al. 계류삭 파단 실험 | 통제 실험 실측 | 신호군·하중 구간·파단 근거 |
| 2 | `synthetic_rope_damage_classification_30k.csv` | 논문 규칙 기반 2차 합성 | 항만 변환의 입력 |

| 5 | Kaggle 복합재 AE 데이터 | 다른 재료의 공개 데이터 | 레거시, 현재 사용 안 함 |

원본 생성 코드 보관이 추가로 필요하다.

## 실제 측정은 어떻게 했나

원 출처는 Bashir et al. (2017)의 동료심사 논문이다.

- 시편: 같은 제조 배치의 24 mm, 12-strand double-braid 폴리에스터 로프 3개(R1~R3)
- 설치: 양 끝을 eye-splice로 만들고 DMaC 대형 동적 인장 시험기에 체결
- 하중: 5~20 kN bedding-in 후, 최소 5 kN에서 최대 하중을 단계적으로 올려 파단까지 반복
- 계측: 로프 양 끝과 중앙에 광대역 hydrophone 3개를 1.6 m 간격으로 배치
- 환경: 로프를 담수에 10 cm 잠그고 센서를 로프에서 약 10 cm 떨어뜨려 수중 음향 측정
- 분석: 배경 시험기 소음을 먼저 측정한 뒤 STFT spectrogram과 도달시간 차이로 신호를 분류·위치 추정

이 시험은 실제 로프 파괴 신호를 측정했지만 **통제된 수중 시험설비 데이터**이며,
실항만의 선박·파랑·조석·센서 클램프 환경을 직접 측정한 것은 아니다.

## 논문에서 가져온 핵심 규칙

| 관찰 | 데이터셋에 반영한 이유 |
|---|---|
| 4개 AE 신호군과 각 진폭·주파수 대역 | 모델 입력 신호군의 기본 구조 |
| 50% MBL 초과 시 저진폭 신호 증가 | `CAUTION` 시작 근거 |
| 70% MBL 초과 시 고진폭 신호 빈발 | `DANGER` 시작 근거 |
| 고진폭 신호에서 최대 약 30 hit | 파단 전 손상 활성도 피처 근거 |
| R1/R2/R3가 76%/77%/87% MBL에서 파단 | 100% 이전에 위험 징후가 필요하다는 근거 |
| 파단 전 신호가 누적·빈발 | 단일 이벤트 대신 최근 윈도를 보는 근거 |

원 논문은 3개 hydrophone으로 20 Hz~50 kHz 범위를 계측했고, 저·중·고진폭 및
저주파→고주파 신호군을 실제 파단 단계와 연결했다.

## 프로젝트 데이터셋은 어떻게 만들었나

`port_domain_synthesis.py`가 아래 순서로 논문 기반 합성 CSV를 항만용 데이터로 바꾼다.

1. 논문의 수중 음압 진폭을 접촉식 피에조 AE 스케일로 재사상한다.
2. 신호 발생 지점과 센서 사이 거리, 주파수별 감쇠, 클램프 결합 손실을 적용한다.
3. 배경 소음보다 6 dB 이상 큰 신호만 검출해 실제 센서의 미탐을 모사한다.
4. 비·바람·크레인·정박선 보조기기 소음과 가짜 이벤트를 확률적으로 주입한다.
5. 64/72/80/88 mm 항만용 로프 시나리오와 온도·습도 값을 부여한다.
6. 세션·시간순으로 정렬하고 `NORMAL/CAUTION/DANGER` 라벨을 유지한다.

결과는 36,115행, 55세션이며 로프 이벤트 20,386개와 환경 교란 이벤트 15,729개다.
`Truth_*`와 하중비는 생성 검증용으로만 남기고 학습 피처에서는 제외했다.

## 무엇이 근거이고 무엇이 가정인가

| 항목 | 근거 수준 |
|---|---|
| 신호군·주파수·하중 단계·파단비 | 원 논문 직접 측정 |
| 40~60 dB AE 검출 임계 범위 | 일반 구조물 AE 실험 문헌 |
| 항만 선박 소음이 저주파 중심이라는 방향 | 항만 소음 측정 연구 |
| 감쇠 `1.0~2.8 dB/m` | 정량 실측이 없는 프로젝트 가정 |
| 클램프 손실 `1.5±0.5 dB` | 프로젝트 가정 |
| 비·바람·크레인 발생률·세기 | 프로젝트 시연 시나리오 |
| 64~88 mm 로프와 MBL 근사 | 제품군을 단순화한 엔지니어링 가정 |

즉 외부 문헌은 **현상과 범위의 방향**을 지지하고, 생성 코드의 모든 숫자를 실측으로
보증하지는 않는다. 가정값은 `port_domain_synthesis.py`의 `PARAMS`에 모아 두었다.

## 왜 이런 데이터셋을 작성했나

1. 기존 Kaggle 데이터는 항공 복합재 손상이라 계류삭과 재료·파괴기구가 달랐다.
2. 계류삭 실측 논문은 실제 파단 물리를 제공하지만 공개된 프로젝트용 행 단위 학습표가 없었다.
3. 논문은 수중 hydrophone, 실제 장치는 연결 고리 접촉식 피에조라 계측 도메인이 달랐다.
4. 항만 소음과 미탐을 넣지 않으면 깨끗한 실험실 데이터만 외우는 모델이 된다.
5. 단일 이벤트는 손상 단계가 겹쳐 최근 12개 신호의 조성·발생률을 묶어야 했다.
6. 같은 세션이 train/test에 섞이지 않도록 GroupKFold로 일반화 가능성을 확인했다.

목표는 실환경 성능을 주장하는 것이 아니라, **실데이터가 오기 전 전체 학습·배포·경보
파이프라인을 검증할 수 있는 정직한 PoC 데이터**를 만드는 것이었다.

## 실제 현장 데이터는 이렇게 수집해야 한다

| 수집 항목 | 방법 |
|---|---|
| 센서 원본 | `sensorId`, `lineId`, UTC 시각, `freqHz`; 가능하면 원파형·FFT도 보관 |
| 계류삭 정보 | 재질, 직경, 길이, 선형밀도, MBL, 설치 위치, 사용 기간 |
| 정답값 | 시험용 load cell 장력, 정기검사 손상 등급, 교체·파단 기록 |
| 환경값 | 풍속, 강우, 파랑·조석, 선박/크레인 가동 상태를 같은 시각으로 동기화 |
| 정상 기준선 | 계류삭별 slack/정상/고장 근접 상태의 진동수 분포 |
| 수집 단위 | 로프·접안 세션 단위로 묶고 train/test도 로프·세션 단위로 분리 |

운영 중인 로프를 고의로 파단시키지 말고, **시험설비의 단계 하중 시험 + 실제 운항 장기
관측 + 교체 시점 검사 결과**를 결합해야 한다. 이 데이터가 확보되면 감쇠·클램프 손실·
slack/critical Hz를 재추정하고 현재 합성 데이터 성능 수치를 폐기·갱신한다.
