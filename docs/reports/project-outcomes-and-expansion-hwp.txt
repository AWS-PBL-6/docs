2. 프로젝트 기대 효과

가) 인명 안전 — 중대재해(스냅백) 예방

스냅백은 계류삭 파단 시 로프가 고장력으로 튕겨 나가며 발생하는 대표적 사망 사고 유형으로, 사고 발생 후에는 대응이 불가능하고 사전 인지·대피만이 유효한 대책임. 본 시스템은 파단 이전 단계에서 위험 징후를 3단계(NORMAL/CAUTION/DANGER)로 조기 판정하고(위험 클래스 재현율 0.97 — 위험을 놓치지 않는 지표를 최우선으로 설계), DANGER 확정 시 스냅백 위험반경을 3D 관제 화면에 즉시 표시하며 SNS 이메일·SMS로 현장 관리자·작업자에게 동시 전파함. 센서 측정에서 경보 전파까지 전 과정이 자동화되어 있어, 인지 지연 없이 대피·작업중지 판단에 필요한 시간을 확보하는 효과를 기대할 수 있음.

다) 안전보건 관리체계 고도화 — 중대재해처벌법 대응

모든 센서 이벤트·위험 판정·경보 발송이 추적 ID(traceId)로 연결되어 DynamoDB(이벤트·알림 이력)에 감사 가능한 형태로 보존됨. 위험 판정 근거(클래스별 확률, 모델 버전, 측정 원본값)와 대응 안내가 함께 기록되므로, 사업장 안전보건 관리 체계의 상시 감시 항목을 보강하고 사고 발생 시 원인 규명·재발 방지 대책 수립의 데이터 근거로 활용 가능함.

라) 관제 효율 및 대응 품질 향상

부산항 3D 디지털 트윈 위에 선박·계류삭·볼라드·위험반경을 통합 표시하여 "어느 계류삭이, 어느 방향으로, 몇 미터가 위험한가"를 표·수치가 아닌 공간 정보로 즉시 인지하도록 함. 또한 위험 발생 시 Bedrock RAG가 승인된 한국 공식 안전문서(부산항 안전기준 매뉴얼 등 7건)에서 검색한 근거를 인용해 즉시 조치·후속 조치 지침을 생성하므로, 관제 인력의 판단 부담을 줄이고 대응 행동의 일관성·규정 정합성을 높임.

마) 상태 기반 교체(condition-based replacement)

계류삭·와이어를 사용 시간이 아닌 실제 상태 데이터에 근거해 교체함으로써, 사용 가능한 로프의 조기 폐기를 줄이고 파단 후 파편 비산·유실을 예방함. 환경적 효과는 부차적이며 핵심 가치는 인명 안전에 있음.


3. 활용 가능성 및 확장 방향

가) 실측 데이터 기반 고도화

현재 모델은 계류삭 AE 파단 실측 논문 기반 합성 데이터로 학습한 PoC 단계임. 도메인 변환 가정 파라미터를 코드 한 곳(PARAMS)에 집약해 두었고, SageMaker Processing → Training → Model Registry(승인) → Endpoint 재학습·재배포 파이프라인이 이미 운영 검증되어 있으므로, 현장 실측 AE 데이터 확보 시 전이학습·재보정을 반복 가능한 절차로 수행할 수 있음. 배포 후에는 SageMaker Model Monitor 기반 입력 분포 드리프트 감시와 스케줄 재학습 자동화를 추가하여 모델 품질을 지속 관리하는 방향으로 확장함.

나) 계측 하드웨어 고도화

현재 시연 하드웨어는 1초 구간 임계 초과 횟수를 주파수로 표현하는 저가 구성이며, 노트북이 블루투스-IoT 게이트웨이를 담당함. 향후 ① Wi-Fi 지원 ESP32 등 엣지 장치의 IoT Core 직접 접속(디바이스 인증서·상호 TLS), ② 고속 샘플링·FFT 기반 실제 AE 특징 계측, ③ 항만 현장 조건에 맞는 통신 방식(LTE·LoRa 등) 적용으로 현장 운영 안정성을 높일 수 있음. 백엔드는 센서 종류를 이벤트 계약(ae-feature-event.v2)으로 수용하므로 하드웨어 교체 시에도 클라우드 파이프라인 변경이 최소화됨.

다) 적용 대상·현장 확장

- 인접 장비 확장: 크레인 와이어, 리프팅 슬링 등 고장력 선재가 사용되는 인접 설비로 동일한 AE/진동 조기경보 구조를 적용 가능
- 다중 센서 확장: 계류삭당 다중 센서 배치 시 도달 시간차 기반 파손 위치 추정으로 발전 가능
- 다중 항만 확장: 데이터 모델이 site/berth 단위로 설계되어 있고, 지식베이스가 일반 규정(scope=general)과 항만별 규정(scope=port-specific)을 분리 관리하므로 타 항만 확장 시 해당 항만사의 승인 규정 문서만 등록하면 대응 안내가 현장 규정 우선으로 동작함(부산항 외 울산항 통합안전매뉴얼 등 이미 등재)
- 안벽 디지털 트윈 연계: 현재 모사 트윈을 실제 안벽 도면·좌표 체계와 연계하면 실운영 관제 화면으로 전환 가능

라) 운영 체계 고도화

상용 운영 단계 진입 시 다음 항목을 우선 보강함: WebSocket 접속($connect) Cognito JWT 인증, SNS SMS 샌드박스 해제(production access) 및 지출 한도 상향, 경보 채널 다중화(브라우저 푸시·경보음·관제실 대형 화면), Amplify GitHub 연동 CI/CD, 프론트·백엔드 공용 상수의 계약 기반 단일 소스화.

나) 시스템 통합 성과

수집(엣지) · 분석(추론) · 전파(관제)의 3-계층이 표준 이벤트 계약으로 연결되어 클라우드에서 실제로 동작함을 실기기로 확인함. 실제 압전센서 측정값이 MQTT로 발행되면 센서-계류삭 배정 검증, 윈도 특징 집계, SageMaker 추론, 시간적 정책·주파수 대역 정책 확정, 스냅백 반경 계산, DynamoDB 저장, WebSocket 화면 갱신, 이메일·SMS 발송까지 사람 개입 없이 완료되며, 시연 하드웨어의 정수 Hz 판독에 맞춘 판정 대역(1~2 Hz 정상 / 3~5 Hz 주의 / 6 Hz 이상 위험)을 백엔드·프론트 동일 기준으로 운영 반영함.

다) 신뢰성 설계 성과

안전 시스템 관점의 신뢰성 요소를 설계 단계부터 반영함.

- 오경보 억제: 단일 측정이 아닌 12-이벤트 윈도 판정 + 시간적 정책(EMA·연속 초과 요건·해제 히스테리시스) + 물리(주파수 대역) 가드 정책의 3중 구조
- 순서 정합성: 병렬 처리 환경에서 과거 결과가 최신 상태를 덮지 않도록 측정 시각 조건부 갱신·statusCurrent 플래그 설계
- 노이즈 격리: 유휴 대역 측정은 실시간 텔레메트리로만 발행하고 ML 이벤트 생성을 차단, 지연·역순·미래 시각 판독 거부
- 근거 있는 안내: 대응 지침은 모델 임의 생성이 아니라 승인 공식 문서 검색 결과를 인용하도록 제한하고, 검색 근거가 없으면 보수적 기본 안내로 대체
- 개발 병행성: SageMaker·실센서 미연결 상태에서도 내장 대체 분류기·가상 센서 모드로 각 팀이 서로를 차단하지 않고 개발 가능

라) 산출물

- 운영 시스템: AWS 단일 팀 계정(ap-northeast-2) 내 CloudFormation 스택(ae-sentinel-app), SageMaker 엔드포인트, Bedrock KB, Amplify 프로덕션 호스팅
- 코드 저장소: Frontend / Backend / Edge-IoT / ML / docs / org 프로필 6개 저장소(AWS-PBL-6)
- 문서 체계: 아키텍처 결정 기록, 팀 간 인터페이스 계약(JSON Schema), 데이터셋 근거·신뢰성 검증 보고, 운영 정책·계정 가이드, 진행·배포 보고 등 30여 건의 현행 문서
