## 2. 프로젝트 개요

### 2.1. 프로젝트명

**AE-Sentinel : 음향 방출(Acoustic Emission) 기반 계류삭 파단 예측 및 스냅백 위험구역 관제 시스템**

### 2.2. 한 줄 설명

저가형 음향 방출(진동) 센서와 AWS 서버리스 AI 파이프라인을 결합하여, 항만·조선소 안벽의 계류삭(밧줄)이 완전히 끊어지기 이전 단계에서 발생하는 내부 섬유 파괴 신호를 조기에 탐지하고, 파단 시 예상되는 스냅백(snap-back) 위험구역을 실시간으로 산출·전파하는 산업 안전 관제 시스템이다.

### 2.3. 역할 (프로젝트 포지셔닝)

본 시스템은 산업 안전관리 체계에서 두 가지 역할을 담당한다. 첫째, 장비 상태에 기반한 사전 예측, 즉 예지 보전(Predictive Maintenance)이다. 둘째, 파단이 임박했을 때의 인명 대피 유도이다. 기존 CCTV 기반 솔루션이 안전모 착용 여부와 같은 '사람의 행동'을 관측 대상으로 삼는 것과 달리, 본 시스템은 '계류삭이라는 장비 자체의 파괴 임박'을 직접 관측 대상으로 삼는다는 점에서 관측의 초점이 다르다.

### 2.4. 세부 주제

재료공학 비파괴검사(NDT) 분야에서 확립된 음향 방출 원리를 저가 IoT 및 클라우드 AI로 이식하여, 섬유·와이어 계류삭의 '파단 직전 이상 주파수 패턴'을 분류하는 예지 보전 모델을 개발하고, 판정 결과를 안벽 도면 위 위험구역(데드존) 시각화로 연결하는 것을 세부 주제로 한다.

## 3. 문제 정의

### 3.1. 해결하고자 하는 문제

항만과 조선소 안벽에서 대형 선박을 고정하는 계류삭과 크레인 와이어는 상시 큰 장력을 받는다. 노후화·마모로 인해 줄이 순간적으로 끊어지면, 저장된 탄성에너지가 반동(스냅백)으로 방출되며 주변 작업자를 타격해 중대재해로 이어진다.

이미지 캡션:

- 사진 1-a) 선내의 실제 와이어 장치 사진
- 사진 1-b) 선박의 실제 훗줄(고정줄) 사진

실제 사례로, **2026년 6월 22일 전남 영암군 HD현대삼호 조선소 1돌핀안벽에서 선박 접안(계류) 작업 중 대형 계류 로프가 끊어져, 튕겨 나온 밧줄에 맞은 40대 근로자 1명이 사망하는 중대재해가 발생했다.** 후속 취재에 따르면 선박이 움직이며 메인 로프를 지지하던 보조 로프가 먼저 끊어진 정황과, 2인 1조 및 신호수 배치 원칙이 지켜지지 않은 점 등이 지적되었으며, 고용노동부는 산업안전보건법·중대재해처벌법 위반 여부를 조사 중이다.

스냅백 사고가 특히 위험한 이유는 다음과 같다.

- 겉보기에는 정상으로 보이던 줄이 약 0.1초 만에 파단되어, 사람이 인지하고 회피할 시간을 확보하기 어렵다.
- CCTV 기반 비전 AI는 줄이 끊어지는 '그 순간'만 포착할 수 있어, 사고를 사전에 막는 예방 수단이 되기 어렵다.
- 야간·해무(바다 안개)·강우 등 악천후 상황에서는 광학 기반 비전 AI의 신뢰도가 크게 저하된다.

- 사진 2-b) snap-back 사고 인명 피해 사례 기사

## 4. 제안 솔루션

### 4.1. 솔루션 개요

**핵심 원리는 음향 방출(Acoustic Emission, AE)이다.** 섬유나 금속이 파단에 이르기 전, 내부의 미세 가닥이 순차적으로 끊어지면서 인간의 가청 영역 밖의 고주파 탄성파를 방출한다. 이는 교량·항공기·복합재 구조물의 비파괴검사에서 널리 쓰이는 확립된 기법이며, 매트릭스 균열·섬유 파단·층간 분리 등 손상 유형이 서로 다른 AE 시그니처를 가진다는 점이 다수 연구와 특허로 뒷받침된다.

탈착식 압전 센서를 계류삭 아이·스플라이스 인근 또는 볼라드 접촉부에 설치하여, 섬유 손상·비정상 마찰·미끄러짐 과정에서 발생하는 고주파 진동 및 음향 신호를 수집한다. 볼라드 기준 센서와의 비교를 통해 주변 설비 진동과 로프 기인 신호를 구분하고, 현장 실데이터 확보 후 AE 기반 파손 분류 모델로 고도화한다.

AWS 서버리스 파이프라인으로 실시간 분류한다. 파단 위험이 판정되면 백엔드 물리 엔진이 스냅백 반경을 계산하고, 생성형 AI가 현장 작업자용 경보문과 대시보드 렌더링 데이터를 생성하여 즉시 전파한다. 이로써 '사후 감지'에서 '사전 예측'으로 패러다임을 전환한다.

### 4.2. 핵심 기능

- 계류삭 상태 상시 관측: 라인별 상태를 정상·주의·위험 3단계로 실시간 표시한다.
- 파단 임박 조기 경보: AE 이상 주파수 패턴을 AI로 분류하여, 완전 파단 이전 단계에서 위험을 통지한다.
- 스냅백 위험구역 산출: 선박 제원·장력·배치 데이터를 바탕으로 파단 시 예상 반경(데드존)을 계산·시각화한다.
- 현장 즉시 전파: Amazon SNS로 주변 작업자 전원에게 대피 알림을 발송한다.
- 통합 관제 대시보드: 안벽 도면 위에 각 계류 라인의 상태와 경보를 오버레이로 표시한다.

## 5. 기대 효과

### 5.1. 환경적 영향

계류삭·와이어를 사용 시간이 아닌 실제 상태에 근거해 교체(condition-based replacement)함으로써, 아직 쓸 수 있는 로프의 조기 폐기를 줄이고 자원 낭비를 완화한다. 또한 파단 후 발생하는 파편 비산과 유실을 예방한다. 저가 엣지 디바이스와 서버리스 구조는 상시 가동되는 전용 계측 장비 대비 하드웨어 사용량과 전력 소모를 낮춘다. 다만 본 프로젝트의 환경적 효과는 부차적이며, 핵심 가치는 인명 안전에 있다.

### 5.2. 사회적 가치

- 중대재해 예방: 스냅백은 대표적인 사망 사고 유형으로, 사전 예측과 대피 유도를 통해 인명 피해를 실질적으로 줄일 수 있다.
- 중소 항만·노후 조선소의 접근성: 고가 OEM 솔루션이 닿지 못하는 현장을 저비용 키트로 보완하여, 안전 기술의 사각지대를 줄인다.
- 중대재해처벌법 대응: 사업장의 안전보건 관리 체계 고도화에 기여하고, 사고 원인 규명을 위한 데이터 근거를 남긴다.

## 6. 기술 구현 계획

### 6.1. 사용 기술 스택

#### 6.1.1. AI / ML

- Amazon SageMaker: AE 손상 분류 모델(이진/다중 분류)의 학습 및 실시간 추론 엔드포인트 운영
- Amazon Bedrock: 위험 판정 시 현장용 경보문과 대시보드 렌더링용 JSON 데이터를 생성. 물리 계산은 위임하지 않는다(6.3, 9 참고)
- 데이터셋: Kaggle Acoustic Emission Dataset (복합재 손상 AE 특징 데이터)

#### 6.1.2. AWS 인프라

- AWS IoT Core: MQTT 프로토콜로 엣지 센서 데이터를 수집하고 규칙 엔진으로 실시간 트리거
- AWS Lambda: 센서 데이터 전처리, 스냅백 반경 물리 엔진, 서비스 오케스트레이션을 담당하는 서버리스 컴퓨팅
- Amazon SNS: 현장 작업자 대상 긴급 대피 알림 발송
- 보조: Amazon S3(데이터 적재), Amazon CloudWatch(로그·모니터링)

#### 6.1.3. 프로그래밍 / 툴체인

- 엣지: ESP32 / Arduino (C·C++), 압전 진동 센서
- 백엔드: Python (Lambda), boto3 SDK
- 프론트엔드: React 기반 관제 대시보드(주력). 초기 프로토타이핑에는 Streamlit을 대안으로 활용한다.

### 6.2. 시스템 아키텍처 (3-계층 모듈형)

전체 시스템은 수집(엣지) · 분석(추론) · 전파(관제)의 3-계층 모듈형으로 설계하여, 각 계층을 독립적으로 개발·검증·확장할 수 있도록 한다.

| 계층 | 구성 요소 | 역할 |
| --- | --- | --- |
| 계층 1 수집 / 엣지 | ESP32 + 압전 진동 센서 -> AWS IoT Core | 볼라드 부착 센서가 고주파 진동을 감지하여 MQTT로 클라우드에 전송한다. |
| 계층 2 분석 / 추론 | AWS Lambda -> Amazon SageMaker -> (위험 시) Lambda 물리 엔진 + Amazon Bedrock | 수집 데이터를 전처리해 SageMaker로 분류하고, 위험 판정 시 스냅백 반경을 계산하며 Bedrock이 경보 콘텐츠를 생성한다. |
| 계층 3 전파 / 관제 | Amazon SNS + React 대시보드 | 작업자에게 즉시 알림을 발송하고, 안벽 도면 위에 위험구역(데드존)을 시각화한다. |

그림 캡션:

- 그림 3) 예상 AWS 서비스 아키텍처

데이터 흐름 요약:

`ESP32(진동 수집) -> IoT Core(MQTT 수집) -> Lambda(전처리) -> SageMaker(AE 분류) -> [위험] Lambda 물리엔진(스냅백 반경) + Bedrock(경보·JSON 생성) -> SNS(대피 알림) + React 대시보드(데드존 시각화)`

### 6.3. 데이터 활용 계획

데이터셋: Kaggle의 'Acoustic Emission Dataset'을 사용한다. 이 데이터는 복합재 부품이 다양한 응력 조건에서 방출한 AE 신호를 담고 있으며, 손상 유형을 정상(No Damage)·매트릭스 균열(Matrix Cracking)·섬유 파단(Fiber Breakage)·층간 분리(Delamination) 4종으로 라벨링한다. 특징 변수로는 최대 진폭(peak amplitude), 방출 에너지(energy release), 지속시간, 상승시간, 주파수와 함께 하중·온습도 등 환경 변수, 섬유·수지 종류 등 재질 변수가 포함된다.

활용 방식과 한계: 본 데이터셋은 항만 계류삭이 아니라 복합재 부품을 대상으로 한 합성(synthetic) 데이터이므로 도메인 갭이 존재한다. 따라서 본 PoC에서는 이를 '파단 직전 AE 시그니처의 대리(proxy) 데이터'로 활용하여, 데이터 파이프라인이 클라우드에서 실시간으로 분류·경보를 수행함을 검증하는 데 목적을 둔다. 실제 현장 적용 단계에서는 계류삭 재질(섬유·와이어)에 대한 AE 데이터를 별도로 수집·라벨링하여 전이학습 또는 재학습하는 과정이 필수적이다.

시연 매핑: 발표장에서는 산업 규모의 장력을 재현할 수 없으므로, 엣지 키트가 만들어내는 마찰 진동 값을 데이터셋의 특징 범위로 스케일링하여 SageMaker에 주입한다. 이 과정이 시뮬레이션임을 명확히 고지하며, 제한된 환경에서 시스템을 검증(PoC)하는 설계 의도로 설명한다.

## 9. 추가 사항

### 9.1. 개발 일정 (2주 로드맵)

| 주차 | 목표 |
| --- | --- |
| 1주차 | AWS 아키텍처 및 데이터 스키마 확정, Kaggle 데이터셋 확보 및 분류 모델 1차 학습, 엣지 센서 키트 조립·MQTT 연결 검증 |
| 2주차 | IoT -> Lambda -> SageMaker -> Bedrock -> SNS 파이프라인 통합, 데드존 물리 엔진 및 React 대시보드 구현, 엔드투엔드 통합 시연 리허설 |

### 9.2. 리스크 및 대응

- 센서 감도 한계: 저가 센서는 실제 산업 규모의 AE를 직접 포착하기 어렵다. 발표에서는 마찰 진동 시뮬레이션으로 대체하되, 이를 제한 환경 PoC 설계로 명확히 설명한다.
- 도메인 갭: 항공 복합재 데이터로 학습한 모델의 현장 일반화 한계는, 향후 계류삭 실데이터 수집·전이학습 계획으로 보완한다.
- 생성형 AI 신뢰성: Bedrock은 물리 법칙을 직접 계산하지 않고, Lambda 물리 엔진이 계산한 좌표를 받아 서술·JSON 가공만 수행하도록 역할을 제한하여 환각(hallucination) 위험을 통제한다.

### 9.3. 확장 가능성

현장 계류삭 실데이터 확보 후 전이학습, 다중 센서를 활용한 파손 위치 추정, 안벽 디지털 트윈 연계, 크레인 와이어·리프팅 슬링 등 인접 장비로의 적용 확대를 향후 과제로 둔다.
