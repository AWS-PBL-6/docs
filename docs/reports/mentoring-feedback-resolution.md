## 1. 결론 요약

리스크 7건 중 5건은 구조적으로 해소, 2건(합성 데이터·운영 점검)은 "해소 주장"이
아니라 "정직한 관리"로 대응하는 것이 정답인 항목임. 특히 멘토링 시점 이후
**학습 데이터셋 자체를 교체**하여 최대 리스크(도메인 갭)의 성격이 바뀌었음.

| 멘토 지적 | 상태 | 근거 |
| --- | --- | --- |
| ① 데드존 물리엔진 노드 미표기 | 반영 | 발표 덱 아키텍처에 "스냅백 반경 계산" 독립 노드 표기 |
| ② Bedrock 역할 표기 불일치 | 해소 | 실제 구현이 "KB 검색 + 경보 리포트 생성" 둘 다로 확장 |
| ③ Kaggle 복합재 도메인 갭 (최대 리스크) | **데이터 교체로 갭의 축 자체를 변경** | Kaggle proxy 폐기 → 계류삭 실측 논문 기반 합성 |
| ④ 저가 센서의 kHz AE 포착 곤란 | 설계 전환으로 해소 | AE 직접 계측 주장을 버리고 측정 가능한 물리량으로 전환 |
| ⑤ ESP32 ADC 샘플링레이트 불일치 | ④와 함께 해소 | 수 Hz 대역 설계라 저가 ADC로 충분 |
| ⑥ IoT 인증 · SageMaker 비용/리전 점검 | 완료 | 상호 TLS + 토픽 신원 검증, 단일 리전, Serverless 종량 과금 |
| ⑦ 1주차 인터페이스 계약 우선 합의 | 완료 · 초과 달성 | JSON Schema 계약 6종+, 계약 변경 프로세스 문서화 |

## 2. 항목별 상세 — 해소 근거와 발표 반박 스크립트

### ① 스냅백 '데드존 물리엔진' 노드 미표기 (권고: 별도 노드 분리 표기)

**해소 현황**

- 발표 덱 아키텍처 슬라이드의 분석 레인에 "스냅백 반경 계산"이 독립 노드로 표기됨
- 정확한 사실관계: 물리엔진은 별도 Lambda 함수가 아니라 **추론 Lambda 내부의
  결정론적 물리 모듈**(`snapback_service`)임 — 발표에서 "별도 Lambda"로 과장하지 말 것

**반박 스크립트**

> "물리 계산은 Lambda의 결정론적 코드가 수행하고 Bedrock에는 위임하지 않습니다.
> 생성형 AI는 계산 결과를 서술할 뿐입니다."

멘토가 종합 평가에서 강점으로 꼽은 지점("Bedrock에 물리계산 위임 안 함 → 환각 통제
명확")과 동일 논리이므로, 지적을 강점으로 되돌리는 답변이 가능함.

### ② Bedrock을 KB(RAG)로 표기 — 실제 역할(경보 리포트 생성)과 불일치

**해소 현황**

- 멘토링 시점에는 표기와 역할이 어긋났으나, 이후 구현이 두 역할을 모두 수행하도록
  확장됨: Bedrock Knowledge Base에서 **승인된 한국 공식 안전문서 7건을 검색(RAG)**
  하고, 검색 인용을 근거로 **경보 리포트(헤드라인 · 즉시/후속 조치 · 근거 인용 ·
  신뢰도)를 생성**하여 이메일 본문과 대시보드 카드에 표시
- 발표 자료 표기는 "Bedrock KB → 근거 인용 경보 리포트 생성"으로 통일

**반박 스크립트**

> "검색 근거가 없으면 생성하지 않고 보수적 기본 안내로 대체합니다 — 표기와 역할이
> 이제 일치합니다."

### ③ 최대 리스크 — 도메인 갭: Kaggle 복합재 AE ≠ 실제 계류삭 섬유 파단

**해소 현황 (가장 중요한 변화)**

- 멘토가 지적한 Kaggle 항공 복합재 proxy 데이터셋은 **폐기하고 레거시 보관** 처리
- 현재 모델은 **계류삭 합성섬유 로프의 실측 AE 파단 실험 논문(Bashir et al. 2017,
  *Applied Acoustics* 121)** 통계 기반 합성 데이터로 학습 — 같은 재료(합성섬유
  계류삭), 같은 파괴 모드(인장 파단)의 실측 연구가 근거
- 항만 도메인 변환(`port_domain_synthesis.py`): 단위 변환 · 거리 감쇠 · 크레인/강우/
  바람 교란 주입, 가정 파라미터는 `PARAMS` 한 곳에 집약(실측 후 재보정 가능)
- 라벨 누수 방지(`Truth_*` 제외), 세션 GroupKFold 검증 — 위험 재현율 0.97
- 갭의 축이 "다른 재료 · 다른 파괴 모드" → "같은 재료 · 같은 파괴 모드의 합성
  근사"로 좁혀짐. 남은 갭(합성 vs 실측)은 검증된 재학습 파이프라인으로 관리

**반박 스크립트 — "해결했다"고 하지 말 것**

> "도메인 갭 지적을 수용해 데이터의 근거를 계류삭 실측 연구로 교체했습니다. 남은
> 갭은 '합성 vs 실측'이며, 이를 위해 ①가정 파라미터를 코드 한 곳에 집약해 재보정
> 가능하게 했고 ②Processing→Training→Registry→Endpoint 재학습 파이프라인을 이미
> 운영 검증했습니다. 실측 데이터가 확보되는 날, 모델 교체는 재배포 한 번입니다."

### ④ 저가 압전센서로 산업규모 AE(수십~수백 kHz) 포착 곤란

**해소 현황**

- 멘토는 "마찰진동 스케일링 시연"으로의 우회를 예상했으나, 실제로는 더 정직한
  구조로 전환: **저가 센서가 kHz AE를 잡는다고 주장하지 않는 설계**
- 센서는 측정 가능한 물리량인 **계류삭 고유 진동수(수 Hz)** 를 측정, taut-cable
  물리 관계(T ∝ f²)로 장력을 추정, 주파수 대역 가드 정책이 최종 판정을 확정
- kHz AE 계측은 이벤트 계약(`ae-feature-event.v2`) 뒤로 추상화 — 향후 FFT 지원
  실 AE 하드웨어로 교체해도 클라우드 파이프라인 변경 없음

**반박 스크립트**

> "kHz AE 계측은 이벤트 계약 뒤로 추상화했습니다. FFT 지원 AE 하드웨어로 교체해도
> 클라우드 파이프라인은 한 줄도 바뀌지 않습니다 — 계측의 한계를 아키텍처 경계로
> 만들었습니다."

### ⑤ ESP32 ADC 샘플링레이트가 실제 AE 대역과 불일치 가능성

**해소 현황**

- ④의 설계 전환으로 함께 해소: 측정 대상이 수 Hz 구조 진동이므로 저가 ADC의
  샘플링레이트로 충분 — kHz 샘플링 요구 자체가 사라짐
- 현 시연 하드웨어는 1초 구간 임계 초과 카운팅(Arduino + HC-06 게이트웨이),
  ESP32 Wi-Fi 직결은 고도화 로드맵에 명시

**반박 스크립트**

> "샘플링 요구를 신호 대역에 맞춰 낮춘 설계입니다. 수 Hz 구조 진동은 저가 ADC로
> 충분히 커버되고, 고속 샘플링·FFT는 하드웨어 업그레이드 경로로 남겼습니다."

### ⑥ IoT Core 인증 · SageMaker 엔드포인트 비용/리전 사전 점검 (권고)

**점검 완료 내역**

- **IoT 인증**: 디바이스 인증서 + 상호 TLS 접속, MQTT 토픽 신원(topicSensorId)과
  페이로드 deviceId 불일치 거부, 미배정 센서 거부(SENSOR_NOT_BOUND), 라인-센서
  바인딩 검증
- **리전**: 전 리소스 ap-northeast-2 단일 리전(SageMaker · Bedrock KB 포함) —
  리전 불일치 리스크 없음
- **비용**: SageMaker Serverless Inference(호출량 과금, 상시 인스턴스 없음, 학습
  과금 150초) + Lambda/DynamoDB 온디맨드 — PoC 비용이 사실상 0에 수렴
- **콜드스타트(~24초)**: 원시 측정값 선반영 설계 + 시연 전 워밍업 호출로 대응

### ⑦ 1주차 인터페이스(스키마·API 계약) 우선 합의 (멘토링 포인트)

**실행 완료 — 완주의 실제 근거**

- JSON Schema 계약 선합의: `ae-feature-event.v2`(센서 이벤트) ·
  `inference-request.v2`/`inference-response.v1`(모델) ·
  `ws-risk-message.v1`(실시간) · `agent-request.v1`(에이전트) + 계약 변경 프로세스
  문서화
- 계약 기반 병렬 개발로 3인이 각 도메인을 독립 진행하고도 E2E 통합에 성공 —
  SageMaker/실센서 미연결 구간은 내장 대체 분류기·가상 센서 모드로 상호 비차단

**발표 활용**: "멘토 권고 → 실행 → E2E 완결"의 인과로 연결하면 멘토링 반영도를
직접 보여주는 스토리가 됨.

## 3. 발표 전략 종합

### 'PoC는 파이프라인 검증이 목적' 프레이밍의 업그레이드

멘토링 포인트였던 이 프레이밍은 이제 한 단계 올릴 수 있음:

> "파이프라인 검증이 목적이었고 — 그 검증이 끝났습니다. 실센서 타격부터 휴대폰
> SMS 수신까지 실기기로 완주했고, 발송 실패 0건입니다."

### 강점 재확인 (멘토 평가 유지 항목)

- 문제 정의 근거(HD현대삼호 실제 사망사고)는 유지하고, 웹 조사로 확보한 최신
  통계(2022~24 사망 10명 + 2025년 7명, 계류 사고 중 파단 관련 53%)로 보강
- "Bedrock에 물리계산 위임 안 함" 환각 통제 구조는 질의응답의 방패로 활용
- 유일한 엣지 HW 포함 → 물리적 E2E 시연 스토리는 시연 리허설(워밍업 포함)로 방어

### 리스크 슬라이드 운영 원칙

- 합성 데이터 · 주파수 프록시 한계를 **먼저 자백**하고 재학습·업그레이드 경로를
  제시하는 순서 유지 (발표 덱 13번 슬라이드 구조와 일치)
- "해결했다"는 표현 대신 "갭의 축을 좁혔고, 남은 갭은 관리 절차가 있다"로 서술
